## 1. 작업 요약

`/coin/[symbol]` 코인룸 6종(btc/eth/xrp/sol/altcoin/kimp)을 **`"use client"` + coin-queries.ts 클라 fetch → async 서버 컴포넌트(SSR)**로 전환했다. 시세·게시글·뉴스·핫이슈·FNG·공식글을 신규 `lib/community/coin-server.ts`(anon Supabase 직접 쿼리 + 5분 ISR)가 서버에서 병렬 fetch하고, 탭 전환 인터랙션만 클라 하위 컴포넌트 `CoinRoomTabs`로 분리했다. JSX·디자인은 R2/T03 그대로 보존하고 altcoin/kimp 집계형 정적 폴백을 유지했다. `generateMetadata`로 코인별 SEO 메타를 추가하고, 6종 슬러그가 고정이므로 `generateStaticParams`로 빌드 프리렌더(SSG+ISR)까지 끌어올렸다.

## 2. ⚠️ 핵심 발견 — mock import는 이미 0건 (오케스트레이션 배경 outdated)

오케스트레이션 문서 §1·§3은 "`coin-queries.ts`가 mock-coins/mock-posts/mock-news를 일부 import(grep 확인됨)"라고 기술했으나 **실제 repo 상태는 이미 mock import 0건**이었다 (R2/T03에서 클라 fetch 실데이터화하며 제거 완료). 즉 **T05의 차단점("coin-queries에서 mock import 0")은 본 작업 이전부터 충족** 상태였고, T04는 이를 SSR 전환과 함께 재확인·고착화했다.

## 4. SSR 전환 범위 + 서버/클라 경계

| 영역 | 렌더 | 비고 |
|---|---|---|
| 브레드크럼 / `CoinHero` / 사이드바(핵심지표·AI시그널·시세·FNG·핫이슈·공식글) | **서버** | `fetchCoinRoomData` 결과를 직접 렌더 |
| 메인 탭(`CommunityTabs` + 5개 탭 패널) | **클라**(`CoinRoomTabs`) | `useState(activeTab)`만 클라. 데이터는 서버 props |

- `CommunityTabs`는 `onChange` 콜백을 받는 클라 컴포넌트라 서버에서 직접 못 쓴다 → 탭 컬럼 전체를 `CoinRoomTabs`(클라)로 분리. props는 모두 직렬화 가능(데이터 객체·문자열)하므로 서버→클라 경계 안전.
- 기존 "불러오는 중…" 로딩 분기는 SSR이라 불필요 → 제거(데이터는 첫 렌더에 이미 존재). **빈 상태 안내·디자인은 그대로 보존**.
- `CoinHero`는 무상태 프레젠테이션(서버 안전). 사이드바 위젯(`PriceTicker/Fng/HotIssue/OfficialPosts`)은 데이터 props만 받아 서버 렌더 OK.

## 5. 데이터 소스 — anon Supabase 직접 쿼리 (self-fetch 회피)

`coin-server.ts`는 `/api/*` 자기 HTTP fetch 대신 **anon Supabase 클라이언트로 직접 쿼리**한다(news-server.ts·메인페이지 R2/T05 동일 패턴). 이유: (1) 쿠키 비의존 anon 클라 + `next.revalidate=300`으로 페이지 정적 prerender 유지, (2) 서버 self-fetch origin 해석 문제 회피, (3) 메인/뉴스 SSR과 일관.

| 데이터 | 소스 | 기존 클라 경로(폐기) | 폴백 |
|---|---|---|---|
| 시세 | `fetchCommunityTickers()` (Binance, lib/supabase/crypto) | `/api/coins/ticker` | `.catch(()=>[])` → 정적 폴백 |
| 게시글(공지/일반) | `community_posts` (board_slug 일치, 최신 30) | `/api/board/coin-{slug}` | `data ?? []` |
| 뉴스 | `news` (symbol.eq OR title/snippet ilike, 최신 30) | `/api/news?query=` | `data ?? []` |
| 핫이슈 | `community_hot_issues` RPC | `/api/coins/hot-issues` | `data ?? []` |
| FNG | `fetchFng()` (Alternative.me, lib/community/fng) | `/api/fng` | `.catch(()=>null)` |
| 공식글 | `blog_posts` (published 3) | `/api/blog?limit=3` | `data ?? []` |

- 뉴스 필터: `coinTagFilter`가 `"ALL"`(kimp)이면 필터 없이 최신, 그 외는 `symbol.eq.{tag},title.ilike.%{tag}%,snippet.ilike.%{tag}%`(/api/news·news-server와 동일 규칙으로 회귀 방지).
- 인기글(`trending`)은 일반글 추천수 상위 10을 서버 정렬.

## 6. altcoin / kimp 집계형 폴백 유지

`buildCoinView(meta, findTicker(tickers, meta.symbol))` — altcoin(symbol `ALT`)·kimp(`KIMP`)는 tickers에 없으므로 `findTicker`가 null 반환 → `staticPrice`/`staticChangePct`/`staticHigh24h`/`staticLow24h`/`volume24hUsd` 정적 폴백 표시. description("단일 코인 시세가 아닌 종합 지표입니다.")도 COIN_ROOMS 메타 그대로. **R2/T03 폴백 동작 무회귀**.

## 8. 렌더 모드 — `●` (SSG + ISR)

- `export const revalidate = 300` + `dynamicParams = false` + `generateStaticParams`(btc/eth/xrp/sol/altcoin/kimp 6종) → 빌드 결과 `/coin/[symbol]`이 **`● (Static, prerendered + ISR)`** 로 6종 전부 프리렌더.
  ```
  ● /coin/[symbol]   1m   1y
    ├ /coin/btc · /coin/eth · /coin/xrp · /coin/sol · /coin/altcoin · /coin/kimp
  ```
- **유효 revalidate가 `1m`로 표시되는 이유**: Binance ticker fetch 내부 `next.revalidate=60`이 페이지 모든 fetch revalidate의 **최솟값**으로 채택됨(Next.js 규칙). 시세가 5분이 아닌 1분마다 신선해지는 셈이라 코인룸엔 오히려 유리. 게시글/뉴스 등 Supabase 쿼리는 anon 클라의 300s revalidate.
- `dynamicParams = false`: 6종 외 슬러그는 `notFound()` 이전에 404 처리(잘못된 코인 라우트 차단).
- 메인페이지(`/`)는 쿠키 기반 `createClient`라 `ƒ`(동적), 본 페이지는 anon 클라라 `●`(정적)로 더 나은 캐시 효율 확보(news-server 패턴 계승).
