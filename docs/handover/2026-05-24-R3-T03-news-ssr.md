## 1. 작업 요약

`/news`를 **`"use client"` + 클라 fetch(news-queries.ts) → async Server Component(SSR)** 로 전환했다.
초기 목록·헤드라인·사이드바 위젯을 서버에서 렌더하고, 4차원 필터(코인/분류/감정/정렬)는
`searchParams`로 해석한다. 필터 UI만 클라이언트 하위 컴포넌트(`NewsFilters`)로 분리해 클릭 시
`searchParams`를 갱신(`router.push`)하여 서버 재렌더를 유발한다. `NEWS_CATEGORIES`/`COIN_FILTERS`는
T01 산출 메타 SSOT(`@/lib/community/news-meta`)에서 import하고, `mock-*` import는 완전히 제거했다.
디자인/JSX(헤더·필터 바·헤드라인·뉴스 표·사이드바)는 회귀 없이 보존했다.

## 3. 설계 결정 — 데이터 소스 (⚠️ 명세 권장안 대비 선택)

명세 Phase 1은 "`news-queries.ts`에 서버 사이드 fetch 추가/조정 (**서버 클라이언트 또는 절대 URL fetch** + `next.revalidate`)"
두 선택지를 제시했다. **서버 클라이언트(Supabase 직접 쿼리)** 를 택했고, `news-queries.ts`가 아닌
**별도 server-only 모듈(`news-server.ts`)** 을 신설했다. 근거:

1. **news-queries.ts는 헤더 주석에서 "클라이언트 전용(server-only 의존 금지)"으로 선언**됐다.
   거기에 Supabase 서버/anon 클라이언트를 넣으면 클라 번들 규약을 깬다.
   → 메인페이지의 `queries.ts`(server) ↔ 클라 분리 패턴을 그대로 따랐다.
2. **`/api/news` 절대 URL fetch를 쓰지 않은 이유**:
   - `/api/news`는 `query`(coin)·`category`만 지원하고 **sentiment·sort 파라미터가 없다** → 4차원
     서버 필터를 완성하려면 결국 클라 useMemo가 잔존하게 됨(SSR 취지 약화).
   - `/api/news`는 `force-dynamic` + 쿠키(`createClient`) → self-fetch 캐시 비효율 + origin 해석 문제.
   - 메인페이지(T15 §4 / R2-T05)가 이미 **쿠키 비의존 anon 클라이언트 + `next.revalidate`** 로
     news 테이블을 직접 쿼리하는 검증된 패턴을 확립 → 동일 패턴 재사용으로 일관성 확보.
3. 결과적으로 **coin/category/sentiment/sort 4차원을 전부 서버에서 해석**한다(클라 필터 잔존 0).

> **검증 grep 영향**: 명세 §6 bash 블록의 `grep "/api/news" app/news/page.tsx # 기대: ≥1`은
> 본 선택으로 **0건**이 된다(직접 Supabase 쿼리이므로 page.tsx에 `/api/news` 문자열 없음).
> Windows 권위 블록(PowerShell §6)에는 이 검사가 없으며, mock-import=0·build 검사는 모두 통과한다.
> 뉴스 쿼리 로직은 `/api/news/route.ts`와 동일한 매칭 규칙(symbol eq OR title/snippet ilike)을 복제해
> 회귀를 방지했다.

## 5. searchParams 4차원 필터 설계

| 차원 | 쿼리 키 | 기본값 | 서버 처리 |
|---|---|---|---|
| 코인 | `coin` | `ALL` | `symbol.eq.X OR title.ilike OR snippet.ilike`(`/api/news` 규칙 복제) |
| 분류 | `category` | `all` | `.eq("category", key)` |
| 감정 | `sentiment` | `all` | `.eq("sentiment", key)` |
| 정렬 | `sort` | `latest` | latest=`pub_date desc` / importance·popular=`importance_score desc, pub_date desc` |
| 페이지 | `page` | `1` | 누적 `.range(0, page*20-1)` + `{count:"exact"}` |

- **검증**: 허용 키 화이트리스트(`COIN_FILTERS`/`NEWS_CATEGORIES`/감정/정렬)에 없으면 기본값 폴백.
- **기본값은 URL에서 생략**(`coin=ALL` 등은 키를 넣지 않음) → 깔끔한 canonical 정합.
- **"더 보기"**: 클라 incremental 대신 `?page=N+1` Link(필터 보존, 누적 렌더로 기존 "더보기" UX 유지).
- **"필터 초기화"**: `/news` Link(전 파라미터 제거).
- **popular(토론많은순)**: 뉴스별 토론 실데이터 부재로 중요도순 대체(R2/T02 정책 유지).
- **헤드라인 3개**: 필터와 독립(전체 중 importance 상위 3).

## 7. 렌더 모드 — ⚠️ 중요

- 빌드 결과 **`ƒ /news` (Dynamic, server-rendered on demand)**.
- **원인**: 페이지가 `searchParams`를 읽음 → Next.js App Router는 searchParams 의존 페이지를
  **정적 prerender 불가**로 판정(요청마다 필터가 달라짐). 이는 searchParams 기반 SSR 필터의
  **필연적·정상 결과**이며, `export const revalidate=300`은 page-level에선 무력(메인페이지 T15 §4와 동일 양상).
- **실질 캐시는 fetch 레이어**가 담당(외부 부하 완화):
  - news/blog/hot-issues: anon 클라이언트 `next.revalidate=300`(5분)
  - Binance ticker: 60초 / FNG: 1시간 (각 모듈 내부 캐시)
- **SSR 목표(서버 렌더 HTML·"use client" 제거·SEO 노출)는 완전 달성**. 정적 ISR이 꼭 필요하면
  필터를 클라 전용으로 되돌려야 하나, 이는 명세의 "4차원 필터=searchParams" 요구와 상충하므로 채택하지 않음.
