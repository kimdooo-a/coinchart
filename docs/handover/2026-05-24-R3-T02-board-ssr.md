# R3 / T02 — 게시판 3종 SSR 전환 + 새 메타(board-meta) 적용

- **라운드**: R3 (community-finish)
- **터미널**: T02 / 12 (Wave 2 — dep T01 board-meta 선행 완료)
- **일시**: 2026-05-24

## 1. 작업 요약

R2/T01에서 게시판 3종은 `"use client"` + `board-queries.ts` 클라 fetch로 실데이터화됐다.
R3/T02는 **SEO 강화를 위해 목록·상세를 SSR(서버 컴포넌트)로 전환**하고, 인터랙션(정렬/검색/페이지 · 추천/비추/댓글/수정·삭제·공유)을 `searchParams` 또는 클라이언트 하위 컴포넌트로 분리했다.
정적 메타(`BOARD_META`/`BoardSlug`)는 T01이 분리한 **`@/lib/community/board-meta` SSOT**에서 import하도록 전환 → **board 디렉토리에서 `lib/community/mock-*` import 0건** 달성 (T05 mock 삭제 선행 조건 충족).

참고 패턴: R1/T15 메인페이지 SSR (`lib/community/queries.ts`의 `fetchMainPageData` — supabase 서버 클라 직접 조회 + 변환 헬퍼).

## 2. SSR 전환 범위 & 서버/클라 경계

| 라우트 | 전환 후 | 서버(SSR) 책임 | 클라 하위 컴포넌트 |
|--------|---------|----------------|--------------------|
| `/board/[slug]` (목록) | 서버 컴포넌트 | searchParams 파싱 → 목록·공지 fetch·렌더, 페이지네이션 baseHref | `BoardListControls`(카테고리 탭·정렬·검색) |
| `/board/[slug]/[postId]` (상세) | 서버 컴포넌트 | 글+댓글+이웃글 fetch·렌더, `generateMetadata`, view_count +1 | `PostActions`(수정/삭제/공유) · `PostVoteButtons`(추천/비추) · `CommentSection`(댓글) |
| `/board/[slug]/write` (작성) | 클라 유지(폼 본질상 인터랙티브) | — | (페이지 자체가 클라) `BOARD_META` import만 board-meta로 교체 |

**경계 원칙**: 서버는 데이터 fetch·초기 렌더(HTML에 콘텐츠 포함 → SEO)만, 사용자 액션(상태 변경 fetch)은 전부 클라 하위 컴포넌트가 `board-queries.ts`의 클라 fetch 래퍼를 호출. 초기 댓글(`initialComments`)은 서버가 SSR로 넘겨 클라 컴포넌트의 초기 상태로 주입 → 첫 페인트에 댓글 포함.

## 3. searchParams 설계 (목록)

| 파라미터 | 의미 | 기본/생략 규칙 |
|----------|------|----------------|
| `page` | 페이지(1-base) | 미지정 → 1 |
| `sort` | `latest`\|`popular`\|`comments`\|`views` | 화이트리스트 외/생략 → `latest` (URL에선 생략) |
| `search` | 제목 검색어(ilike) | 공백 trim, 빈 값 생략 |
| `category` | 카테고리 필터 | 미지정/`전체` → 필터 없음(URL에서 생략) |

- `BoardListControls`(클라)는 현재 필터에 partial을 병합해 URL 생성 후 `router.push` → 서버 재렌더. **필터 변경 시 page는 1로 리셋**(page 파라미터 생략).
- 검색은 **350ms 디바운스** 후 URL 반영(Enter 시 즉시).
- 페이지네이션은 `Pagination` 컴포넌트의 `baseHref` 모드(쿼리스트링 `<Link>`)로 **서버 렌더** — 현재 필터(category/sort/search) 보존하고 `page=`만 교체.

## 4. generateMetadata (상세 SEO)

- 상세 페이지에 `generateMetadata` 추가: `{글 제목} - {게시판명}` title + 본문 평문 요약(`summarizeHtml`, 120자) description + OG(`type: "article"`).
- 본문 조회는 `getPostRecord`를 **React `cache()`로 래핑** → `generateMetadata`와 페이지 본문 렌더가 동일 요청 내에서 **1회만 DB 조회**(dedupe). 메타 생성은 **부수효과 없음**(view_count 증가 안 함) → 조회수 중복 증가 방지.
- 목록 페이지에도 `generateMetadata`(게시판명·설명) 추가.

## 5. 데이터 레이어 (신규 board-server.ts)

`@/lib/supabase/server`(next/headers cookies) + `@/lib/supabase/admin`을 쓰는 **서버 전용 모듈**. 클라 컴포넌트에서 import 금지(server-only 강제는 supabase/server가 대신).

| 함수 | 역할 |
|------|------|
| `fetchBoardListServer(slug, opts)` | 공지+일반글 병렬 fetch. 정렬/검색(ilike)/카테고리 규칙은 **GET /api/board/[slug]와 동일** |
| `getPostRecord(slug, postId)` | 글 본문 단건 조회 (React cache, 부수효과 없음) |
| `fetchBoardPostServer(slug, postId)` | 글+첫 페이지 댓글(100) + view_count +1(admin client, best-effort) |
| `summarizeHtml(html, maxLen)` | HTML 태그 제거 → 메타 description용 평문 요약 |

- SELECT 필드(`POST_LIST_FIELDS`/`POST_DETAIL_FIELDS`/`COMMENT_FIELDS`)는 API 라우트 응답 계약과 일치하게 정의 → 매퍼 재사용 가능.
- `board-queries.ts`의 매퍼·row 타입을 **export로 승격**해 서버/클라가 공유: `toBoardListItem`·`toBoardPostDetail`·`toBoardComment` + `PostListRow`·`PostDetailRow`·`CommentRow`.
- `BoardSlug`는 board-meta SSOT를 `board-queries.ts`가 **re-export** → 기존 `@/lib/community/board-queries`의 BoardSlug import 경로도 무파손.
