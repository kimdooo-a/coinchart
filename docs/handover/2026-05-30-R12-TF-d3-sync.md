## 2. 동기화 흐름 (로그인 → sync → DB 소스)

### (a) 익명
- 변경 없음. `localStorage('cca:watchlist')` 단일 소스. 상한 30.

### (b) 로그인 직후 1회 sync (taste #2 로컬 우선 병합)
1. `auth.getUser()` 또는 `onAuthStateChange`에서 회원 확인 → `runSync()`.
2. 현재 로컬 목록(`getSnapshot()`)을 `POST /api/watchlist/sync {items}`로 업로드.
3. 응답 `items`(DB 병합 진실)를 `serverToLocal` 매핑 후 `writeAndEmit` → **localStorage가 DB 진실의 미러로 전환**.
   - 새 기기 로그인 시: 로컬 비어 있어도 sync가 빈 배열 업로드 → 응답에 DB 전체 목록 → 로컬 복원(= "목록=GET" 효과를 sync 응답 1콜로 달성, 별도 GET 불필요).
4. `result.skipped > 0`이면 `notice = {type:'sync-skipped', count, limit:100}` 노출.
5. **모듈 전역 가드 `moduleSynced`**: 훅 인스턴스가 여럿(W2의 ⭐ 토글 다지점)이어도 로그인 세션당 **sync 1회**. `await` 전에 선점 → 인스턴스 경합 시 중복 sync 차단. sync 실패 시 `false` 리셋 → 다음 auth 이벤트 재시도. 로그아웃 시 `false` 리셋 → 다음 로그인 재동기화.

### (c) 회원 상태의 add/remove/clear (DB 소스 전환)
- **add**: 낙관적 로컬 추가(동기 `boolean` 계약 유지) → `POST /api/watchlist`. 실패/409 시 로컬 롤백.
- **remove**: 낙관적 로컬 제거 → `DELETE /api/watchlist?assetType=&symbol=`. 실패 시 제거 항목 로컬 복원.
- **clear**: 낙관적 로컬 비우기 → 회원이면 항목별 `DELETE` 전건 발사(벌크 삭제 엔드포인트 없음). DB 잔여 행이 다음 로그인 sync로 부활하는 것을 막기 위해 전건 삭제 시도.
- **reorder**: 로컬 전용 유지(DB 미반영). T-C sync는 기존 행 `sort_order`를 갱신하지 않고, 지시서 §3도 reorder DB 동기화를 요구하지 않음 → **스코프 외**(아래 §5 후속).

## 3. 409 · 충돌 · 정규화 처리

- **POST 409(서버 상한 100)**: `apiAddItem`이 `'limit'` 반환 → 로컬 롤백 + `notice = {type:'limit', limit:100}`. 클라 낙관 가드(`curLimit=100`)가 1차 차단하므로 409는 타 기기로 DB가 이미 100인 경우에만 발생.
- **sync 상한 초과**: 서버가 신규분을 입력 순서로 잘라 `skipped` 보고 → `notice = {type:'sync-skipped'}`. 로컬 손실 0(taste #2: 합집합·중복 DB 유지).
- **심볼 정규화 일치(T-C §6)**: 로컬 `normalizeSymbol`(trim·대문자) = 서버 `normalizeWatchlistInput`(trim·대문자). CRYPTO=`BTCUSDT`/STOCK=`AAPL` 표기 동일. UNIQUE(user_id,asset_type,symbol) 충돌은 서버 `ON CONFLICT DO NOTHING`(sync)·멱등 add(`alreadyExists`)로 흡수.
- **createdAt 형 차이**: 서버 ISO 문자열 → `serverToLocal`에서 `Date.parse` → unix ms(파싱 실패 시 `Date.now()` 폴백).
- **인증 전달**: `@supabase/ssr` `createBrowserClient` 쿠키 세션 → same-origin `fetch`가 쿠키 자동 전송 → 서버 라우트 `auth.getUser()` 인증 인식. **토큰 수동 부착 불필요.**

### `notice` 안내 신호 (호출부 선택 구독)
```ts
type WatchlistNotice =
  | { type: 'limit'; limit: number }
  | { type: 'sync-skipped'; count: number; limit: number };
// useWatchlist() 반환에 notice: WatchlistNotice|null, dismissNotice() 추가.
```
T-E(`WatchlistView`)가 후속으로 `notice`를 토스트/배너로 표면화 가능(현재 미구독이어도 무해).

## 5. 미해결 / 후속

- **reorder DB 영속화**: 현재 로컬 전용. 드래그 정렬 영속이 필요하면 후속 라운드에서 sort_order 갱신 엔드포인트(T-C 영역) + 훅 연동.
- **clear 벌크 삭제**: 항목별 N개 DELETE. 종목 수 많을 때 비효율 → 후속 시 `DELETE /api/watchlist?all=1`(T-C 영역) 검토.
- **notice UX 표면화**: T-E `WatchlistView`가 `notice`/`dismissNotice` 구독해 토스트 노출(W2/후속).
- **운영 DB 적용**: 위 §4 선행 조건.
