## 응답 스펙

`GET /api/fng` → `200`:

```json
{
  "value": 28,
  "classification": "Fear",
  "prevValue": 28,
  "timestamp": 1779494400000
}
```

- `value`: 0~100 정수
- `classification`: `"Extreme Fear" | "Fear" | "Neutral" | "Greed" | "Extreme Greed"`
- `prevValue?`: 어제 값 (없을 수 있음)
- `timestamp`: unix ms

## 캐시 정책

- **TTL**: 1시간
- **계층**: (a) 모듈 메모리(`let cache`) (b) Next.js `revalidate = 3600` (route 파일 + fetch 옵션 둘 다)
- 처음 호출 시 외부 fetch, 이후 1시간 내 호출은 메모리 캐시 히트 → 외부 API 부하 최소
- 위젯이 메인페이지 SSR/ISR로 호출하면 페이지 캐시 정책에 의해 추가로 더 길게 살 수 있음

## T15에 남기는 메모

- 호출 엔드포인트: **`GET /api/fng`**
- 위젯 props는 그대로(`value`, `prevValue?`, `label?`) — 매핑은 단순:
  - `value` ← `snapshot.value`
  - `prevValue` ← `snapshot.prevValue` (있을 때만)
  - `label`은 굳이 넘기지 않아도 위젯이 한국어 라벨을 자체 매핑함. 영문 라벨을 원하면 `snapshot.classification` 전달.
- **외부 API 다운 시 502** — 위젯 호출부에서 try/catch 또는 fetch 응답 status 체크 후 **fallback UI** 노출 권장 (예: 회색 게이지 + "데이터 불러올 수 없음"). 현재 하드코딩값(`value={72} prevValue={68}`)을 fallback으로 재사용해도 무방.
- 서버 컴포넌트에서 직접 `import { fetchFng } from "@/lib/community/fng"` 호출도 가능 — 이 경우 `/api/fng` 우회. 정책 결정은 T15.
