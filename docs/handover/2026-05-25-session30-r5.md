### 토픽 2: #4 마이그레이션 히스토리 정합
세션 29 우려(Management API 적용분이 schema_migrations 미기록 → 차후 db push 시 CREATE POLICY 충돌)를 해소.

- **축 A(코드 멱등화)**: 커뮤니티 2파일의 CREATE POLICY 18개(create_community_tables 15 + comment_likes 3)에 `DROP POLICY IF EXISTS` 선행 추가 → 차후 db push 재실행 안전. 아직 어떤 환경 schema_migrations에도 등록 전이라 파일 사후 수정 부작용 없음.
- **축 B(backfill) 진단**: 운영 DB `schema_migrations`를 Management API로 **읽기 조회** → version이 **파일명 8자리 날짜**라 같은 날짜 다수 파일(`20260523`×3·`20260524`×2)이 version 충돌. **단순 backfill 불가** — 파일명 14자리 정규화가 선행돼야 함. 멱등화로 실질 안전이 확보됐으므로 **운영 DB 직접 변경은 하지 않고** 정합 경로를 런북 §9에 문서화.

**결론**: 멱등화로 차후 충돌 해소(`e75a77c`). backfill은 정식 db push 환경 구축(파일명 정규화 + config.toml)과 묶어 이월.

### 토픽 4: #2 detail API 비추 집계 노출
게시글 상세에서 `PostVoteButtons`가 `initialDislikes` 미전달 → 클릭 전 비추 0 표시 문제.

- `like_count`는 `SUM(value)` 순합산이라 순수 추천 수가 아님. 분리 집계는 RPC `community_post_like_counts`가 담당.
- page.tsx는 SSR이라 `board-server.fetchBoardPostServer`를 사용(클라 `fetchBoardPost`는 **사용처 0** — R3 SSR 전환 후 미사용). → detail API route는 안 건드리고 SSR 경로만 정확히.
- `BoardPostDetail.dislikes` 추가 + `toBoardPostDetail(row, counts?)` (counts 미제공 시 like_count 폴백·dislikes 0 — 하위호환). board-server가 RPC를 댓글 조회와 병렬 호출해 정확값 채움. page.tsx가 `initialDislikes` 전달.
- 운영 DB에서 RPC 반환 키(`like_count`·`dislike_count`) 라운드트립 확인.

**결론**: SSR 경로 비추 초기값 정확 노출(`a1f437c`). tsc 0 / build green.

### 토픽 5: #1 T04 E2E 회수/검증 (kdye2e)
R4 마감 시 L-B4(댓글 추천)만 실패(앱버그 아님 판정). 풀 검증 + spec 신뢰성 개선.

- **원인 확정**: error-context 스냅샷으로 시드 게시글 댓글 0("댓글 0개") → 추천 대상 ThumbsUp 부재로 timeout. L-B3와 독립이라 의존 불가.
- **해결**: L-B4가 추천 대상 댓글을 **자체 생성** 후 그 댓글 추천(독립·결정적). L-B3·L-B4 모두 `waitForResponse`로 POST 201·PATCH 확정(낙관적 UI false positive 방지).
- dev 서버를 운영 DB URL 주입으로 기동 → `E2E_DB_READY=1` 풀 실행 → **29 passed / 0 failed / 1 skipped(AD1)**. E2E 생성 댓글은 Management API로 정리(잔여 0).

**결론**: L-B4 해결 + DB 의존 5건 활성·통과(`77d3547`). solution [[e2e-db-dependent-test-reliability]] 기록.
