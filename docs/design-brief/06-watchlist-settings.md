## 0. 이 문서의 위치

`/watchlist`·`/settings`는 R10에서 **의도적으로 구현 제외**된 "준비 중(Coming Soon)" 스텁이다(신규 기능이라 기획 선행 필요·병렬 부적합 판정). 본 문서는 **무엇을·어떻게·어떤 데이터로 만들지**를 확정해 후속 구현 라운드(R12 후보)의 입력을 만든다.

두 페이지를 한 문서로 묶은 이유: **settings의 "알림" 그룹이 watchlist에 의존**하고, 두 페이지 모두 "익명 사용자에게 개인화 데이터를 어떻게 줄 것인가"라는 동일한 핵심 질문을 공유하기 때문이다.

## 1. 현황 분석

### 1-1. `/watchlist` (현 스텁 — `app/watchlist/page.tsx`, 66줄)

- **내용**: "관심종목" 타이틀 + 아이콘 3개(⭐ 즐겨찾기 / 📈 실시간가격 / 🔔 알림) + "관심종목 기능 준비 중" 안내 + "분석 페이지로 이동" CTA. **기능 0**.
- **스텁이 약속한 기능**: "코인과 주식을 즐겨찾기하고, 실시간 가격 변동 알림을 받을 수 있는 기능".
- **진입점**: 헤더 "도구 ▼" 드롭다운("워치리스트", `docs/design-brief/00-overview.md` §7).
- **현 디자인 톤**: 그라디언트·블러·`rounded-3xl` — 이는 **v1.0 다크 프리미엄 잔재**. v2.0 네이버 톤(`00-overview.md` §2 회피 사항: 그라디언트·네온·큰 라운드 금지)으로 **재정렬 필요**.

### 1-2. `/settings` (현 스텁 — `app/settings/page.tsx`, 78줄)

- **내용**: "설정" 타이틀 + 3개 그룹 카드(🔔 알림 / 🛡 보안 / 🎨 테마) 각각 "구현 예정" 표기 + "홈으로" CTA. **기능 0**.
- **스텁이 약속한 그룹**:
  - 알림 설정 — "이메일 및 푸시 알림을 관리합니다."
  - 보안 설정 — "비밀번호 및 2단계 인증을 관리합니다."
  - 테마 설정 — "화면 테마 및 언어를 설정합니다."
- **진입점**: 현재 GNB 직접 노출 없음(스텁 단계). 로그인 후 사용자 드롭다운 또는 "도구 ▼"에 편입 예정.
- **현 디자인 톤**: watchlist와 동일한 v1.0 잔재 → 재정렬 필요.

### 1-3. ⚠️ 스텁 약속과 v2.0 방향성의 충돌 (핵심 발견)

스텁의 약속(이메일/푸시 알림, 비밀번호·2FA, 테마 토글)은 **"회원 가입형 SaaS"를 전제**한다. 그러나 v2.0은 **익명 게스트가 1급 시민인 코인판식 커뮤니티**(`PROJECT_DIRECTION.md` §3, 익명+회원 혼용)이고, **1차는 라이트 모드 고정**(§6-2), **언어 토글은 이미 헤더에 존재**(`LanguageContext`)다. 따라서 스텁 문구를 그대로 구현하면 v2.0과 충돌한다 → **§4에서 솎아낸다**.

### 2-2. 인증 모델 — **localStorage(익명) + DB 동기화(회원)** 2단계

**핵심 결정**: 즐겨찾기는 community의 익명 모델(`guest_nickname` + `guest_password_hash`, `_SCHEMA_REFERENCE.md` community_posts)을 **재사용하지 않는다**.

- **근거**: 게시판 익명 모델은 "글마다 닉+비번 입력"이 전제다. 즐겨찾기는 별 하나 누를 때마다 비번을 받을 수 없다(UX 파탄). 또한 즐겨찾기는 공개 콘텐츠가 아니라 **순수 개인 상태**라 IP 마스킹·추천 dedup 같은 community 장치가 전혀 불필요하다.
- **결정**:
  1. **익명(기본)**: 즐겨찾기를 `localStorage`에 저장. 서버 0, DB 0, 로그인 0. 기기·브라우저에 종속(기기 바꾸면 사라짐 — 익명의 자연스러운 한계).
  2. **회원(선택)**: 로그인 시 localStorage 목록을 DB로 1회 머지 업로드 → 이후 기기 간 동기화. 비로그인→로그인 전환 시 **로컬 우선 병합**(중복 심볼 무시).
- **v2.0 정합**: 익명은 추가 인증 없이 즉시 사용(코인판 정신), 회원은 부가 가치(동기화)로 유도. 회원 강제 없음.

### 2-3. 데이터 모델 후보 (회원 동기화 단계에서만 DB)

`community_*` 접두사는 **게시판 도메인**이므로 차용하지 않고 `user_*` 네임스페이스를 신설한다. `secure_memos`(본인만 CRUD, `user_id` FK → auth.users)와 동일한 **개인 소유 데이터 패턴**을 따른다.

```sql
-- supabase/migrations/202612xx_create_user_watchlist.sql (R12 구현 시)
CREATE TABLE user_watchlist (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  asset_type  TEXT NOT NULL CHECK (asset_type IN ('CRYPTO','STOCK')),
  symbol      TEXT NOT NULL,          -- CRYPTO: 'BTCUSDT' / STOCK: 'AAPL'
  sort_order  INTEGER NOT NULL DEFAULT 0,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (user_id, asset_type, symbol)
);
CREATE INDEX idx_user_watchlist_user ON user_watchlist (user_id, sort_order);
-- RLS: secure_memos와 동일 — 본인(user_id = auth.uid())만 SELECT/INSERT/UPDATE/DELETE
```

- **심볼 표기**: CRYPTO는 Binance pair(`BTCUSDT`) — `lib/supabase/crypto.ts`의 `fetchBinanceTickers` 입력 형식과 일치. STOCK은 티커(`AAPL`) — `/api/stock/quote` 입력과 일치. **SSOT 규칙**(crypto는 `lib/supabase/crypto.ts`, stock은 `lib/supabase/stock.ts`)을 그대로 유지하기 위해 시세는 각 SSOT 경로로 조회한다.
- **localStorage 스키마(익명·MVP)**: DB 컬럼과 1:1 대응되는 JSON으로 두어 회원 전환 시 머지를 단순화.
  ```ts
  // key: 'cm.watchlist.v1'
  { items: [ { assetType: 'CRYPTO', symbol: 'BTCUSDT', sortOrder: 0, addedAt: 1748... }, ... ] }
  ```

### 2-4. API 후보

| 용도 | 엔드포인트 | 신규/재사용 | 비고 |
|------|-----------|------------|------|
| 즐겨찾기 **코인** 시세 | `GET /api/coins/ticker?symbols=BTCUSDT,ETHUSDT` | **재사용** | 즐겨찾기 심볼 CSV 전달. 60초 캐시 그대로 활용 |
| 즐겨찾기 **주식** 시세 | `GET /api/stock/quote?symbol=AAPL` | **재사용** | 심볼별 호출(현 스펙은 단건) |
| 회원 목록 조회 | `GET /api/watchlist` | **신규** | 회원 전용, RLS로 본인 행만 |
| 즐겨찾기 추가 | `POST /api/watchlist` `{ assetType, symbol }` | **신규** | 회원 전용 |
| 즐겨찾기 삭제 | `DELETE /api/watchlist` `{ assetType, symbol }` | **신규** | 회원 전용 |
| 로컬→DB 머지 업로드 | `POST /api/watchlist/sync` `{ items[] }` | **신규** | 로그인 직후 1회. 중복 심볼 무시(UNIQUE 충돌 → ON CONFLICT DO NOTHING) |

> **핵심**: 시세 조회 API는 **신규 0개** — 기존 ticker/quote를 그대로 재사용한다. 신규 API 4개는 모두 회원 동기화용(MVP에서는 익명 localStorage만으로 시세 표시까지 완결되므로 신규 API 없이도 MVP 동작 가능). 주식 시세 **다건 배치 조회**가 필요하면 `GET /api/stock/quotes?symbols=` 신설을 R12에서 검토(미결정 §5).

```
┌─ Header (공통) ──────────────────────────────────────────────────────┐
├─ 페이지 타이틀: ⭐ 관심종목   [＋ 종목 추가]            [코인] [주식] 탭 │
├──────────────────────────────────────────────────────────────────────┤
│ 정렬 ▼ (추가순/이름/등락률)                          🔄 60초마다 자동갱신 │
│ ┌──────────────────────────────────────────────────────────────────┐ │
│ │ 심볼      현재가         24h 등락        거래량      [차트][룸][✕]  │ │  ← 헤더행
│ ├──────────────────────────────────────────────────────────────────┤ │
│ │ ₿ BTC    $132,400      ▲ +1.58%        $34.2B      [📊][💬][✕]    │ │  ← 빨강(상승)
│ │ Ξ ETH    $4,820        ▼ -0.74%        $18.1B      [📊][💬][✕]    │ │  ← 파랑(하락)
│ │ ... (1줄 = 1종목, zebra 배경, 호버 강조)                          │ │
│ └──────────────────────────────────────────────────────────────────┘ │
│ (빈 상태) "아직 관심종목이 없습니다. 코인룸이나 차트분석에서 ⭐를 눌러보세요." │
└──────────────────────────────────────────────────────────────────────┘
```

- **표 1줄 = 1종목** (`00-overview.md` §9-1 BoardRow 정신 차용). 카드형 금지.
- **상승=빨강 / 하락=파랑** (`00-overview.md` §3-4 한국식, 필수).
- **종목 추가 플로우**: `[＋ 종목 추가]` → 심볼 검색 모달(코인/주식 탭, 자동완성) → 선택 시 즉시 목록 추가. **별도로** 코인룸 히어로(`05-coin-room.md` §3-1)·차트분석 페이지에 "⭐ 관심추가" 토글을 심어 **현장 추가**도 지원(주 추가 동선).
- **행 액션**: `📊` 차트분석(`/analysis/{symbol}` 또는 `/stock/{symbol}`), `💬` 코인룸(`/coin/{symbol}`, 코인만), `✕` 삭제.
- **실시간 시세**: 60초 폴링(ticker 캐시 주기와 일치). 변동 시 가격 깜빡임(`05-coin-room.md` §5와 동일 패턴).

### 2-6. 진입점·연동

- 헤더 "도구 ▼"의 "워치리스트" 유지.

## 3. settings 기획

### 3-1. 스텁 3그룹 현실성 평가 (솎아내기)

| 스텁 그룹 | v2.0 적합성 | 판정 |
|----------|------------|------|
| 🔔 알림(이메일/푸시) | watchlist 알림이 v3.0이라 **의존 대상 부재**. 익명에게 이메일 알림 불가. | ❌ **제거** (MVP). v2.2에 "목표가 브라우저 알림 on/off"만 부분 부활 |
| 🛡 보안(비밀번호/2FA) | 회원 인증이 **OAuth(구글/카카오) 중심**(`PROJECT_DIRECTION.md` §3-1)이라 자체 비밀번호·2FA는 Supabase Auth와 **이중 관리·과설계**. 익명에겐 해당 없음. | ❌ **제거**. "로그인 상태·연결 계정 표시 + 로그아웃"만 회원 영역에 남김 |
| 🎨 테마/언어 | 테마=**1차 라이트 고정**(§6-2, v2.1 다크)이라 토글 줄 게 없음. 언어=**이미 헤더 토글 존재**(LanguageContext) → 중복. | ❌ **제거** (중복·미래기능). 다크 추가 시(v2.1) "테마" 부활 |

→ **스텁 3그룹 모두 MVP에서 솎아낸다.** 그대로 두면 "구현 예정"만 영원히 반복하는 빈 껍데기가 된다.

### 3-2. 대신 남길 것 — 익명에게도 동작하는 "표시 환경설정"

v2.0에서 **진짜로 의미 있는 설정**은 로그인과 무관하게 **클라이언트 표시 옵션**이다(localStorage 저장, 서버 0).

| | 등락 색상(한국식 빨↑파↓ / 글로벌 녹↑빨↓) | v2.1 | 기본=한국식. `00-overview.md` §3-4 |
| | 숫자 표기(축약 $34.2B / 전체) | v2.2 | |
| **관심종목** | watchlist 바로가기 + 회원 동기화 상태 | v2.1 | §2 연동 |
| **데이터** | 로컬 데이터 초기화(watchlist·최근 본 종목·검색 기록) | v2.1 | 익명 데이터 관리권 |
| **계정**(회원만) | 로그인 계정·연결 OAuth 표시 + 로그아웃 | v2.1 | 보안 그룹의 현실적 대체 |

| **알림**(보류) | 목표가 브라우저 알림 on/off | v2.2 | watchlist 알림 구현 후 |

- 토글·세그먼트는 `00-overview.md` §9-4 탭/§10 인터랙션 톤 차용. 카드 보더 1px·`rounded-md`(큰 라운드 금지).
- 설정 변경은 **즉시 반영**(저장 버튼 없음) → localStorage 기록 → 전역 Context로 전 페이지 시세 표시에 적용.

## 4. 솎아내기 결론 요약

**뺀 것**: 이메일/웹푸시 알림(→v3.0), 자체 비밀번호·2FA(→OAuth로 대체), 테마 토글(→v2.1 다크), 설정 내 언어 토글(→헤더 중복 제거).

**남긴 것**: (watchlist) 즐겨찾기+실시간 시세 표시; (settings) 표시 통화·등락 색상·로컬 데이터 초기화·계정 표시/로그아웃.

**재정의의 핵심**: 스텁이 가정한 "회원 SaaS 설정"을 v2.0 정체성(익명 1급 시민·라이트 고정·OAuth)에 맞춰 **"익명에게도 동작하는 클라이언트 표시 설정"**으로 바꾼다.

## 5. 구현 로드맵 (R12+)

### 5-1. 단계·의존성 (DB → API → UI 순)

| 단계 | 작업 | 의존 | 권장 터미널 |
|------|------|------|------------|
| **W1** | watchlist 디자인 톤 v2.0 재정렬 + localStorage 훅(`useWatchlist`) + 표 UI + 시세 폴링(ticker/quote **재사용**) | 없음(익명 MVP, 서버 0) | T-A |
| **W2** | 현장 추가 ⭐ 토글 공용 컴포넌트 → 코인룸·analysis·stock·시세스트립 4곳 삽입 | W1 | T-A |
| **S1** | settings 톤 재정렬 + 표시 환경설정(통화·색상) Context + localStorage + 데이터 초기화 | 없음(익명) | T-B |
| **S2** | 표시 설정 전역 적용(시세 표시 컴포넌트들이 Context 구독) | S1 | T-B |
| **D1** | `user_watchlist` 마이그레이션 + RLS(secure_memos 패턴) | 없음 | T-C |
| **D2** | `GET/POST/DELETE /api/watchlist` + `/api/watchlist/sync` (회원·RLS) | D1 | T-C |
| **D3** | 회원 동기화: 로그인 시 머지 업로드, watchlist 훅이 회원이면 DB 소스로 전환 | W1·D2 | T-A |
| **N1**(v2.2) | 목표가 브라우저 알림(앱 오픈 시 Notification API) + settings 토글 | W1·S1 | — |

- **Wave 분할**: W1·S1·D1은 **상호 독립**(병렬 가능). W2·S2는 각 선행에 의존. D3는 W1+D2 합류 지점.
- **MVP 경계**: W1+W2+S1+S2까지면 **익명 사용자 기준 완전 동작**(서버 0). D1~D3는 "회원 동기화" 부가가치로 분리 출시 가능.

## 6. Stitch 의뢰 시 추가 지시

```
페이지 명: 관심종목(Watchlist) + 설정(Settings)
타입: 데스크톱 + 모바일
스타일: 네이버 증권 관심종목 표 + 토스/네이버 설정 리스트
요점(watchlist): 표 1줄 = 1종목. 심볼/현재가/등락률/거래량/액션. 상승=빨강·하락=파랑(한국식)
요점(settings): 그룹 카드 + 세그먼트 토글. 저장버튼 없이 즉시 반영. 빈 껍데기 금지(실동작 항목만)
회피: 그라디언트·블러·큰 라운드(현 스텁의 v1.0 잔재 폐기), 풀스크린 히어로
모바일: watchlist 표는 거래량 생략·등락률 강조 1줄 축약
빈 상태: watchlist "⭐로 종목을 담아보세요" + 코인룸/차트분석 유도
```
