## 문제

`kdydispatch`로 발사한 R1 다중 터미널 환경에서 **동일 일꾼(예: T06)이 두 번째 터미널로 또 발사**되는 사례가 반복 발생.

증상:
- 사용자가 새 터미널에 "T06 — ... 실행" 발사 프롬프트를 보냄
- 본 터미널이 작업 명세서를 정독하고 SOT 점검 단계에 진입했을 때 **모든 산출물이 이미 존재**함을 발견
- `git log --oneline`에 `f65f980 feat: 세션 11 (R1/T06) — 뉴스 분류 4차원 DB·API 통합` 같은 커밋이 이미 푸시된 상태

재현 조건:
- R1 multi-terminal dispatch (`/kdydispatch`)
- 일꾼이 이미 별도 터미널에서 완료·커밋·푸시까지 마친 상태에서 동일 일꾼 발사 프롬프트가 재전송됨

## 원인

`/kdydispatch`의 발사 프롬프트 분배는 일꾼별 1회를 가정하지만, 실제로는 다음 시나리오로 중복 발사가 발생할 수 있다:

1. **사용자가 같은 발사 프롬프트를 두 번 복사·붙여넣기** (오타·재시도)
2. **컨덕터 측 발사 큐 재실행** — 일꾼 상태 추적이 끊겨 안전상 재발사
3. **세션 번호 재정렬 시 잘못된 일꾼이 같은 슬롯 차지** — 세션 9 T08 사례(hook payload가 T15로 잘못 주입됨)와는 다르지만 대응 패턴은 동일
4. **R1→R2 라운드 전환 직전에 R1 일꾼 발사가 늦게 도착** — 컨덕터가 이미 통합 후

본 프로젝트에서는 R1 라운드 진행 중 T06 중복 발사가 한 차례 관측됨.

## 해결

재발사 일꾼은 다음 절차를 따른다. **새 산출물을 만들지 않는다.**

### 1) 사전 발견 신호 점검 (작업 시작 전)

작업 명세서 정독 후 SOT 점검 단계에서 아래 3가지 신호 중 하나라도 발견되면 "중복 발사 가능성"을 의심:

- (a) **산출물 경로의 파일이 이미 존재** — `Glob`/`Read`로 확인
- (b) **handover가 이미 작성됨** — `docs/handover/{YYYY-MM-DD}-R{N}-T{XX}-*.md` 존재
- (c) **git log에 동일 일꾼 커밋 존재** — `git log --oneline -10 | grep "T{XX}"` 또는 세션 번호 매칭

### 2) 무결성 재검증만 수행

작업 명세서 §검증 섹션의 모든 명령을 그대로 재실행:

```bash
npx tsc --noEmit | grep -E "{영역 키워드}"
grep -c "{spec이 요구한 키워드}" {파일}
npx eslint {산출물 파일들} 2>&1 | tail -10
```

검증 결과를 기존 handover의 "검증 결과" 섹션과 대조:
- **PASS 일치** → 작업 무결. 손대지 않음
- **불일치 발견** → 이슈 보고. 사용자 결정에 맡김 (재발사 일꾼이 임의 수정 금지)

### 3) 산출물 무변경 원칙

손대지 않는 이유:
- handover 재작성 시 다른 일꾼 작업과의 정합성 깨질 위험
- 중복 변경분이 컨덕터 통합 시 충돌 유발
- 이미 푸시된 커밋 위에 사소한 변경을 얹는 것은 git 이력 노이즈
- "minimal diff" 원칙

### 4) journal에만 "재발사 검증 세션"으로 기록

`docs/logs/journal-{YYYY-MM-DD}.md`에 별도 세션 섹션 append:

```markdown
## 세션 {N} (R{X}/T{YY} 재발사 — 검증 세션)

### [1] 재발사 발견
- 발견 신호 (a)(b)(c) 명시
- 기존 커밋 해시 명시 (예: f65f980)

### [2] 무결성 재검증 결과
- 검증 항목별 PASS 일치 여부

### [3] 산출물 무변경 — 본 세션 코드/spec 변경분 0
```

`current.md`/`logs/{YYYY-MM}.md`/`next-dev-prompt.md`/`handover/` **추가 작성 금지** — 기존 세션 N(원본 발사)의 cs 산출물이 이미 모든 정보를 담고 있음.

### 5) 사용자에게 명확히 보고

발견 시점에 즉시 사용자에게:
- "T{XX} 작업이 이미 완료(커밋 {hash})되어 있음을 발견"
- 무결성 검증 결과 요약
- 추가 진행 사항 문의

## 교훈

- **재발사를 발견했을 때 가장 안전한 행동은 "아무것도 하지 않는 것"**. 변경 없는 검증만 수행하고 journal에 기록.
- 컨덕터 입장에서는 일꾼 중복 발사가 자연스러운 안전 장치이므로 "왜 발사됐는가" 추궁보다 "무결성 유지"가 우선.
- 본 패턴은 모든 멀티터미널 dispatch에 일반화 가능 (R1/R2/RN 무관).
